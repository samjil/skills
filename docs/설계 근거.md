# samjil-handoff 스킬 — 설계 근거

Claude ↔ Antigravity(agy) 파일 대화 채널 규약을 **독립 스킬 및 런타임 통합 구조**로 개편한 기록.
무엇을 왜 그렇게 정했는지, 무엇을 일부러 빼 두었는지만 적는다. 규약 본문은 `SKILL.md`에 있다.

| 항목 | 값 |
|---|---|
| 스킬 정본 | `samjil/skills` (`samjil-handoff/`) — [skills.sh](https://skills.sh) 규약 준수 |
| 원클릭 설치 | `install.ps1` (Antigravity & Claude 전역 등록) |
| agy 연동 | `~/.gemini/config/skills.json` 에 `~/.agents/skills` 경로 등록, 순수 SKILL.md는 `~/.agents/skills/samjil-handoff/`에 배치 |
| Claude 연동 | `~/.claude/skills/samjil-handoff` → `~/.agents/skills/samjil-handoff` 정션(Junction) 연결 |
| 대화 기록 | `~/.samjil/handoff/<프로젝트명>/` — **PC마다 독립 전역 폴더.** |
| 웹 뷰어 연동 | `http://127.0.0.1:8787` (`~/.samjil/viewer/serve-viewer.ps1`) Handoff & Delegate 통합 뷰어 |
| 처음 적용 | 실전 웹 프론트엔드 프로젝트 (메시지 70+건 실전 운용 검증 완료) |
| 개편 일자 | 2026-09-17 (samjil/skills 독립 저장소 분리, skills.sh 호환, 탭 통합 웹 뷰어 내장) |

---

## 1. 왜 독립 스킬 저장소(`samjil/skills`)로 분리했나

기존에는 로컬 클라우드 동기화 드라이브 등에 원본을 두고, 각 PC마다 `skills.json`에 경로를 수동으로 타이핑하거나 정션을 걸어야 했다.
이로 인해:
1. 새 PC에서 작업할 때마다 경로를 기억하고 수동 설정해야 하는 번거로움이 있었다.
2. 스킬 규약 자체가 Git으로 버전 관리되지 않고 로컬 드라이브에만 의존했다.
3. [skills.sh](https://skills.sh) 오픈소스 에이전트 스킬 생태계와 연동하여 `npx skills add` 또는 원클릭 스크립트로 누구나 쉽게 설치할 수 있도록 독립 Git 저장소로 구축했다.

## 2. 왜 대화 기록을 `~/.samjil/handoff` 로 배치했나

특정 프로젝트 저장소나 외부 브리지 도구에 종속되지 않고 영구히 자립하기 위해 사용자 홈 디렉터리의 통합 루트(`~/.samjil/handoff/`)로 표준화했다:

1. **완전한 독립성 및 단일 통합 관리**:
   특정 Git 저장소의 위치가 바뀌거나 폐지되어도 대화 기록은 사용자 PC의 표준 경로(`~/.samjil/handoff/<프로젝트명>/`)에 영구 보존되며, 홈 디렉터리에 여러 점(dot) 폴더가 난립하지 않고 `~/.samjil/` 아래에 스킬명과 1:1로 깔끔하게 통합된다.
2. **Git 격리 보장**:
   프로젝트 코드 저장소 바깥에 존재하므로, 대화가 수천 건 불어나도 프로젝트의 `.gitignore`를 건드리거나 코드 커밋에 실수로 섞일 위험이 0%다.
3. **다중 PC 충돌 원천 차단**:
   PC마다 각자의 홈 디렉터리 경로를 사용하므로, 다른 PC에서 작업하더라도 메시지 번호(`0001`, `0002`...)가 충돌하거나 원장이 덮어써지지 않는다.

## 3. 원클릭 설치 스크립트 (`install.ps1`) 의 도입

### 목적
새 PC, 새 프로젝트, 새 세션에서 사용자가 프롬프트에 스킬 경로나 지시문을 입력할 필요 없이,
저장소 루트에서 **`.\install.ps1` 한 번 실행만으로 전역 스킬이 영구 활성화**되도록 한다.

### 스크립트가 하는 일
1. `~/.gemini/config/skills.json`의 `entries`를 정리한다 — 저장소 경로(`D:\Repos\...`)를 직접
   연결하던 예전 방식은 빼고, 고정 경로 `~/.agents/skills`만 등록한다.
2. 저장소 안의 `samjil-handoff`, `samjil-delegate-agy`, `samjil-git-commit` 등 각 스킬의 순수
   `SKILL.md`만 `~/.agents/skills/<스킬명>/`에 복사한다. Claude Code용으로는
   `~/.claude/skills/<스킬명>`에서 그 폴더로 정션(Junction)을 걸어, 스킬 폴더에는 항상
   `SKILL.md` 하나만 깔끔하게 남긴다.
3. 원격 실행(`irm ... | iex`) 시 GitHub에서 최신 코드를 받아 위 과정을 그대로 수행한다.

## 4. 내장 독립 통합 웹 뷰어 (`runtime/viewer/`, `~/.samjil/viewer/`)

- `runtime/viewer/` 에 통합 HTTP 서버(`serve-viewer.ps1`)와 대시보드 웹 UI(`web/`)를 모듈화하여 브릿지 도구 없이 단독 실행 지원.
- `serve-viewer.ps1` 실행 시 `http://127.0.0.1:8787`에서:
  - **Handoff 탭**: 프로젝트별 원장(`INDEX.md`) 목록을 타임라인 카드로 표시, 상태 배지(`보냄`, `읽음`, `처리됨`, `확인함`, `보류`) 시각화, 마크다운 본문 인라인 렌더링, `BRIEF.md` 프로젝트 맥락 접이식 카드 제공.
  - **Delegate QA 탭**: Antigravity CLI 위임 내역, 실시간 진행 상태, 프롬프트/답변 상세, 토큰 사용량 및 소요 시간 시각화.

## 5. 메시지 작성 주기와 통합 원칙 (기계적 1:1 작성 지양)

- **배경**:
  사용자의 질문이나 피드백은 순서 없이 여러 번 연달아 들어오거나 자잘한 확인 사항이 많다. 이를 매 턴마다 1:1로 `msg/00XX` 파일을 만들면 원장(`INDEX.md`)에 실질적 맥락 없는 파편화된 메시지가 양산되고 토큰과 조회 비용이 낭비된다.
- **원칙 확립**:
  - **모아서 통합 기록**: 간단한 질의응답이나 연관된 작은 수정은 작업 흐름 중에 모아두었다가, 논리적 단위가 일단락될 때 하나의 통합 메시지로 묶어 작성.
  - **즉시 단독 기록**: 답변/작업 분량이 방대하거나 독립적 맥락 보존이 필수적인 중대 사안은 즉시 단독 파일로 분리 작성.

## 6. 자동 이어가기 (2026-10-16)

- **문제**: 채널은 "한쪽이 파일을 쓰고 다른 쪽이 다음 턴에 읽는" 구조라, 사용자가 상대 에이전트에게 매번 "메시지 확인해줘"라고 말해야 했다. 대화형으로 기획했지만 사람이 전달자였다.
- **agy 쪽 = 워처의 펌프**: 워처는 이미 항상 떠 있고 agy 를 부르는 길(inbox → 작업자 → agy, 세션 이어가기)이 있다. 그래서 채널의 새 `c2a` 를 보면 그 길로 위임하고, agy 의 **최종 답변**을 펌프가 회신 파일로 저장한다.
  agy 에게 회신 파일과 원장을 직접 쓰게 하지 않은 이유: 번호 따기·시각·상태 전이·표 형식을 LLM 이 매번 정확히 지키게 하는 것보다 코드 한 곳에서 지키는 쪽이 틀리지 않는다(규약이 "원장을 통째로 다시 쓰지 않는다", "번호는 쓰기 직전에 조회"를 따로 못 박은 이유와 같다).
- **Claude 쪽 = Stop 훅**: 깨울 수 있는 길을 비교했다. ① `claude --resume` 으로 세션을 백그라운드로 깨우기: Desktop 앱이 열어 둔 같은 세션과 동시에 쓰면 기록이 어긋날 위험이 있고 Claude 쿼터를 자동으로 쓴다. ② Stop 훅: 세션이 열려 있는 동안만 동작하지만 같은 세션·같은 맥락에서 이어 가고 충돌이 없다. ②를 택했다(사용자 결정). 세션이 닫혀 있으면 Claude 쪽 자동 이어가기는 없다 — 다음에 열 때 훅이나 "턴을 시작할 때 INDEX 꼬리를 먼저 본다" 규칙이 받는다.
  훅의 `stop_hook_active` 는 보지 않는다. 이 훅은 새 agy 회신이 있을 때만 막고, 같은 회신은 2번까지만 막고, 펌프의 왕복 한도가 전체를 끊기 때문이다(하네스에도 연속 8번 차단 상한이 있다).
- **한도**: 최근 60분에 6회(사용자 결정). 시간 창으로 센 이유: Claude 가 `답장대상` 을 빼먹어도(답장 사슬로 세면 한도가 풀린다) 한도가 지켜지고, 오래 지난 뒤의 새 대화는 자연히 다시 시작된다. 넘으면 `AUTO.json` 의 `halted` 로 멈추고 뷰어에서 사람이 초기화한다.
- **모델 표시**: 뷰어의 "Claude → agy" 를 모델명으로 바꾸려고 메시지 머리말에 `모델:` 을 넣었다. 모델은 쓴 쪽만 확실히 안다(Claude 는 시스템이 알려 준 ID, 자동 회신은 위임 기록의 모델). 머리말이 없는 옛 메시지는 지어내지 않고 Claude/agy 로만 보이며, 받는 쪽은 그 메시지에 답한 메시지의 모델을 쓰고 없을 때만 "가장 최근 모델(추정)"로 표시한다.
- **옵트인**: Stop 훅 등록은 사용자의 Claude Code 전역 설정을 바꾸는 일이라 `install.ps1 -HandoffAutoHook` 일 때만 하고, 바꾸기 전에 백업한다.
- **검증하지 못한 것**: 실제 agy 가 지시문대로 최종 답변을 요약 블록 형식으로 쓰는지, Claude Desktop 앱의 Code 세션이 `settings.json` 의 Stop 훅을 같은 방식으로 실행하고 긴 대기(최대 1900초)를 허용하는지는 이 저장소의 시험(가짜 agy·가짜 훅 입력)으로 확인하지 못했다. 처음 쓸 때 짧은 메시지 한 건으로 한 바퀴 돌려 보고 뷰어의 자동 이어가기 줄과 회신 메시지를 확인한다.
